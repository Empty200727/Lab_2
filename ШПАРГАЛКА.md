## 2. Что за физика

| Что | Формула | Смысл |
|---|---|---|
| Удельный заряд | **q / m** | заряд на 1 кг массы; определяет, как сильно частица отклоняется в электрическом/магнитном поле |
| Комптоновская длина волны | **λc = h / (m·c)** | длина волны фотона, энергия которого равна энергии покоя частицы m·c²; в эффекте Комптона Δλ = λc·(1 − cos θ): при рассеянии фотона на 90° его длина волны увеличивается ровно на λc |
| Приведённая | **ƛc = ħ / (m·c) = λc / 2π** | то же, делённое на 2π |
| Лоренц-фактор | **γ = 1 / √(1 − v²/c²)** | во сколько раз «растёт» масса при скорости v |
| Релятивистский удельный заряд | **q / (γ·m)** | удельный заряд быстрой частицы (меньше, чем у покоящейся) |

- У нейтрона заряд 0 ⇒ удельный заряд 0.
- У электрона заряд отрицательный ⇒ удельный заряд со знаком минус (−1.7588·10¹¹ Кл/кг).
- Протон и нейтрон почти одной массы ⇒ почти одинаковые λc (~1.32·10⁻¹⁵ м); электрон в ~1836 раз легче ⇒ λc в ~1836 раз больше (2.426·10⁻¹² м).
- Комптоновская длина волны считается по **массе покоя**, поэтому от скорости не зависит.
- Константы — CODATA 2018 (`particles/models.py`, строки 27–34).

## 5. Как работает программа (поток данных)

1. `main()` (`main.py`) открывает БД `ResultRepository` через `with` и запускает `ConsoleApp`.
2. Пользователь выбирает пункт меню → словарь `self._actions` вызывает нужный метод.
3. `Particle.create("electron", v)` — фабричный метод находит класс в `Particle.registry`
   и создаёт объект `Electron(v)`. Дескриптор `Velocity` проверяет скорость.
4. `particle.calculate()` считает все величины и возвращает `CalculationResult`.
5. Результат печатается (`__str__`) и сохраняется в БД (`repository.add`).
6. Отчёт: `DocxReportWriter().save(repository.all(), "reports")` — берёт всю историю из БД.

## 6. Возможные вопросы преподавателя

**Что такое абстрактный класс? Почему нельзя создать `Particle()`?**
Класс-наследник `ABC`, у которого есть методы с `@abstractmethod`. Python не даст создать объект,
пока все абстрактные методы не реализованы в наследнике — будет `TypeError`. Это проверяет
тест `test_abstract_classes_cannot_be_instantiated`. `Lepton` и `Hadron` тоже абстрактные:
у них нет `name`, `rest_mass` и т.д.

**Зачем `Lepton` и `Hadron`?** Это промежуточный уровень иерархии, как в физике: электрон — лептон,
протон и нейтрон — адроны (барионы, состоят из кварков). В `Lepton` общее свойство `lepton_number`,
в `Hadron` — `baryon_number` и абстрактный `quark_composition` (uud / udd).

**Что такое managed-атрибут?** Атрибут, доступ к которому контролирует код: `property` или дескриптор.
Например, `electron.velocity = 3e9` вызывает `Velocity.__set__`, который выбросит `ValueError`
(быстрее света нельзя). `electron.rest_mass = 1` — `AttributeError`, т.к. у свойства нет сеттера.

**Чем дескриптор отличается от property?** `property` — это и есть встроенный дескриптор.
Свой дескриптор (класс с `__get__`/`__set__`) удобен, когда одну и ту же проверку надо
переиспользовать в разных классах.

**Что такое dunder-методы? Пример?** «Магические» методы `__имя__`, Python вызывает их сам:
`repr(x)` → `__repr__`, `str(x)`/`print(x)` → `__str__`, `a == b` → `__eq__`, `a < b` → `__lt__`
(поэтому работает `sorted()` частиц — по массе), `len(repo)` → `__len__`, `with repo:` →
`__enter__`/`__exit__`, `writer(results, path)` → `__call__`.

**Что делает `@total_ordering`?** По `__eq__` и `__lt__` достраивает `<=`, `>`, `>=`.

**Что делает `__init_subclass__`?** Вызывается при создании класса-наследника. Строка
`class Electron(Lepton, key="electron")` автоматически регистрирует класс в `Particle.registry`,
и фабрика `Particle.create("electron")` может его найти.

**`@staticmethod` vs `@classmethod`?** staticmethod не получает ни `self`, ни `cls` — обычная функция
внутри класса (`compton_wavelength_for_mass`). classmethod получает класс `cls` — используется
как фабрика (`Particle.create`).

**Что такое пакет и модуль?** Модуль — один `.py` файл. Пакет — папка с модулями и `__init__.py`.
`__init__.py` выполняется при `import particles` и задаёт, что можно импортировать (`__all__`).

**Зачем `with ResultRepository(...) as repo`?** Контекстный менеджер: при выходе из блока
`__exit__` закрывает соединение с БД, даже если была ошибка.

**Почему в SQL `?` вместо подстановки значений в строку?** Параметризованный запрос — защита
от SQL-инъекций и правильное экранирование значений.

**Зачем в Dockerfile сначала копируется requirements.txt?** Docker кеширует слои: если код
поменялся, а зависимости нет, `pip install` повторно не выполняется — сборка быстрее.

**Зачем `-it` и `-v` при `docker run`?** `-it` — интерактивный терминал (программа ждёт ввода).
`-v` — подключает папки с компьютера, иначе БД и отчёты пропадут вместе с контейнером.

**Что тестируется?**
- `test_models.py` — значения q/m и λc сверяются с эталоном CODATA, релятивистский расчёт
  (при v = 0.6c γ = 1.25), запрет создавать абстрактные классы, проверка скорости (отрицательная,
  ≥ c, строка, NaN), запрет менять массу/заряд, фабрика, dunder-методы.
- `test_database.py` — запись, чтение после переподключения, очистка (временная БД `tmp_path` / `:memory:`).
- `test_reports.py` — в docx есть таблица с нужными строками, в xlsx правильные значения ячеек,
  ошибка при пустых данных и пустом заголовке.
- `test_main.py` — разбор ввода скорости (`0.5c`, `1e6`) и полный сеанс меню с подменой `input`
  через `monkeypatch`.
